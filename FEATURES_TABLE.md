# Infinity6 SDK Feature Parity Matrix

This document provides a comprehensive feature-by-feature comparison across the three Infinity6 SDK implementations: **Go (`sdkgo`)**, **Web / JavaScript (`sdkweb`)**, and **Python (`sdkpy`)**.

Specific language implementations, method signatures, behaviors, and nuances are documented directly within each language's column.

## Detailed Nuances & Divergences

### 1. Model Get API (`dsz_model_get`)
* All three SDKs match the backend server schema:
  - Request: `POST /api/model/dataset/{dataset}/signed-get/{model_name}` with JSON body `{"model_version": "...", "model_partitions": {...}}`.
  - Response: Parses `resp.urls` to locate `name == "sqlite.bin"`.

### 2. Method Naming Discrepancies
* **SdkFuncs Accessor:**
  * Aligned across SDKs: `c.Funcs()` in `sdkgo`, `sdk.funcs()` in `sdkweb`, and `client.funcs()` in `sdkpy`.
* **Token Expiration Checks & Renewal:**
  * Supported across SDKs: `sdkgo` (`tokens.GetValidAccessToken()`), `sdkweb` (`tokens.getValidAccessToken()`), and `sdkpy` (`tokens.get_valid_access_token()`) provide automatic silent renewal when tokens are expired or within a safety skew window. All provide explicit expiration inspection helpers (`IsAccessTokenExpired` / `isAccessTokenExpired` / `is_access_token_expired`).

### 3. Telemetry in Inference
* In `sdkgo`, `sdkweb`, and `sdkpy`, calling `infer.Run()` / `infer.run()` automatically emits a `recraw` event containing the raw recommendation results, session ID, and user ID to the ingestion pipeline (`IngestzEventRelevanceFashionEvent` / `ingestzEventRelevanceFashionEvent` / `ingestz_event_relevance_fashion_event`). Subsequently, `infer.SelectResults()` / `infer.selectResults()` / `infer.select_results()` emits a `recshow` event containing only the displayed SKU IDs.
